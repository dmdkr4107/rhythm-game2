# 기획 질문과 개발 계획

## 현재 상태

게임 구현 전입니다. 이 문서는 기획 질문과 향후 개발 순서를 정리하며, 구현 시작을 승인하는 문서는 아닙니다. 사용자 요청이 있기 전에는 게임을 구현하지 않습니다.

## 미정 사항과 기획 질문

| 항목 | 상태 | 결정할 질문 |
| --- | --- | --- |
| 플랫폼 | 미정 | PC, 웹, 모바일 중 어디에서 플레이할까요? 지원할 운영체제와 기기는 무엇인가요? |
| 개발 도구 | 미정 | 어떤 언어, 엔진 또는 프레임워크를 사용할까요? 초보자가 설치하고 수정하기 쉬운 도구는 무엇인가요? |
| 조작 키 | 미정 | 어떤 키나 입력 장치를 사용할까요? 키 변경을 지원할까요? |
| 노트 방식 | 미정 | 노트는 어떻게 나타나고 이동할까요? 레인 수와 탭·길게 누르기 등의 노트 종류는 무엇인가요? |
| 음악 | 미정 | 어떤 음악을 사용할까요? 사용 권한과 파일 형식은 어떻게 확인할까요? |

추가로 결정할 질문:

- 시작, 재시작, 종료 화면은 어떻게 구성할까요?
- 음악 기준 시간과 노트 시간은 어떻게 표현할까요? 지연 보정이 필요한가요?
- 판정 종류와 각 시간 경계는 무엇인가요? 경계값과 같은 입력은 어느 판정에 포함할까요?
- 점수, 콤보, 놓친 노트의 처리 규칙은 무엇인가요?
- 음악이 끝났을 때 남은 노트와 결과 화면은 어떻게 처리할까요?
- 최소한으로 완성할 첫 버전의 범위는 무엇인가요?

## 단계별 개발 계획

모든 단계는 앞으로 진행할 계획입니다. 플랫폼, 개발 도구, 조작 키, 노트 방식, 음악은 사용자의 결정 전까지 미정으로 유지합니다.

1. **기획 확인**: 위 질문에 답하고 첫 버전의 범위와 판정·점수 규칙을 문서화합니다. 미정 항목과 결정된 항목을 구분합니다.
2. **개발 환경 준비**: 결정한 플랫폼과 도구에 맞춰 환경을 구성하고 설치·실행 방법을 기록합니다.
3. **시작과 재시작**: 작은 실행 화면과 상태 전환을 구현하고, 재시작 시 시간이 초기화되는지 확인합니다.
4. **입력 처리**: 결정한 조작 방식으로 입력을 받고 키 반복, 동시 입력, 입력 지연을 확인합니다.
5. **음악과 노트 표시**: 선택한 음악과 노트 데이터를 연결하고 재생 시간 기준 동기화를 확인합니다.
6. **판정 구현**: 합의한 판정 경계와 노트 처리 규칙을 구현하고 경계 직전·경계값·경계 직후를 확인합니다.
7. **점수 계산**: 합의한 점수·콤보 규칙을 구현하고 예상값과 실제값을 비교합니다.
8. **음악 종료와 결과**: 종료 시점, 남은 노트 처리, 결과 표시와 재시작을 확인합니다.
9. **통합 검증**: `CHECKLIST.md`에 환경, 방법, 실제 결과를 기록하고 미확인 항목을 별도로 남깁니다.

각 단계는 필요한 만큼 더 작은 작업으로 나눕니다. 실행 확인 전에는 단계나 체크 항목을 완료로 표시하지 않습니다.
